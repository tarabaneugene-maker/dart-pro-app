#### Почему Windows не рекомендуется для production?

1. **SIGTERM/SIGINT** — на Windows нет нативных сигналов POSIX. Graceful shutdown (R14) через `ProcessSignal.sigterm` не сработает корректно. Придётся использовать `SetConsoleCtrlHandler` или обёртку.
2. **Docker** — Windows-контейнеры менее распространены, большинство хостингов (Railway, Fly.io, Heroku) работают на Linux.
3. **Reverse Proxy** — Caddy и Nginx под Windows есть, но настройка WSS + автопродление SSL сложнее.
4. **SQLite** — на Windows работает, но WAL mode может быть менее стабильным при конкурентном доступе через SMB/сетевые диски.
5. **Стоимость** — лицензия Windows Server дороже, чем Linux VPS.

#### Когда Windows всё-таки можно использовать?

- Если сервер уже развёрнут на Windows и нет возможности мигрировать
- Для локального тестирования и разработки (start_server.bat)
- Для небольшого количества пользователей (< 10) без требований к HA

#### Что нужно сделать для Windows production:
- Заменить `ProcessSignal.sigterm` на `SetConsoleCtrlHandler` (Win32 API)
- Использовать Nginx для Windows или IIS ARR для reverse proxy
- Настроить планировщик задач для автостарта и мониторинга
- Использовать Windows Firewall вместо iptables
- Рассмотреть IIS WebSocket support вместо отдельного reverse proxy
